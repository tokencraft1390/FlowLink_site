What Makes LoopVault Different

Onchain inputs, explicit gatesThe prototype evaluates live borrower health and applies profitability/risk criteria rather than treating every detected event as executable.

Non-custodial directionLoopVault is being developed around execution control rather than a model that requires this dashboard to take custody of user funds.

Evidence Contract

The public feed is intentionally simple. The monitoring process can write sanitized observations into loopvault-evidence.json. The page only renders records marked as observations; it does not sign transactions or expose execution credentials.

Minimum publishable fields: timestamp, redacted borrower identifier, health factor, economic-gate result, risk-gate result, and final monitor-only decision. Transaction hashes should only be included when they refer to genuine public onchain activity and are safe to disclose.
